# Security

Report vulnerabilities through GitHub's private vulnerability reporting (Security tab, "Report a vulnerability"). Do not open a public issue.

You can expect an acknowledgement within a few days. Say in the report what is affected and how to reproduce it.

**In scope:** the site's code and build (pages, scripts, the in-browser example runner and, once it exists, the in-browser search agent), the CI workflows, and the deploy configuration.

**Out of scope:** the content of the posts, and third-party embeds (Sandpack, StackBlitz) beyond how this site loads them.

The blog has no accounts and no server-side secrets. Tests must not need real credentials.
